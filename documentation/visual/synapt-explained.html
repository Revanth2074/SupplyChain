Synapt is a giant, smart library. Our app talks to it with a walkie-talkie.

The library remembers 100,000 old supply-chain problems and how people fixed them. When a new problem happens, our app picks up the walkie-talkie (the MCP connector), presses the right button, and the library answers. This page explains every button, what it does, and where our app uses it.

The walkie-talkie (MCP connector)

The only way to talk to the library. It has 17 buttons. Press one, say your question, get an answer.

backend/synapt/synapt_connector.py — SynaptMCPConnector. Model Context Protocol = JSON-RPC 2.0 over HTTPS; answers can stream back as server-sent events.

The library card (token)

Before talking, we show our name and password and get a card. No card, no talking.

authenticate() posts the username/password from backend/.env to the auth service and gets a bearer token; on a 401 it logs in again automatically.

Our own shelf (provider)

The library is shared with other people, but we have our own shelf with our name on it. We only read our shelf.

SYNAPT_PROVIDER_ID=supply_chain_disruptions. The connector adds provider_id to every call automatically when the tool accepts one.

The librarian (trident_query)

The cleverest button: you ask a whole question, the librarian reads, follows the web of ideas, and answers in words with a “how sure am I” score.

Graph-RAG: retrieve chunks → seed graph nodes → walk up to 2 hops → generate a grounded answer with confidence, knowledge/procedural/graph confidence and a reasoning subgraph.

The 4 rooms in the library

Synapt keeps different kinds of memory in different rooms. Here is what we put in each one, and what we get out.

📖

Knowledge room

Stories of old problems, cut into small pages, plus a spider web that links ideas.

We put in:
  • 4,000 case cards (40 files)
  • profiles of all 100,000 cases
  • summary statistics + an ontology
Chunks + Neo4j graph. Our provider: 894 nodes, 1,038 edges, 688 chunks. Read with trident_get_chunks, trident_search, trident_query.
🧾

Recipe room

Step-by-step recipes: “if a port is jammed, do step 1, then step 2…”.

We put in:
  • 6 response playbooks, one per disruption type, 7 steps each
Procedure Store. trident_get_procedures returns ordered steps; our Planner turns them into the action plan.
📔

Diary room

A diary of past conversations, so the library can say “we saw something like this before”.

We get:
  • past episodes and mined patterns
  • our 👍/👎 ratings help it learn
Episodic memory. trident_episodes inspects it; trident_query uses it (episodes_used); trident_feedback records verdicts.
🏷️

Sticker room

Old tickets with stickers on them. Show a new ticket, and it guesses the right stickers from look-alikes.

We put in:
  • 5,000 labelled tickets (uploaded as .xlsx in the Synapt console)
Ticket store. trident_label_ticket predicts labels like recovery outcome from nearest neighbours, with confidence and support.

What happens in one real analysis

A user types “Ransomware hit our Tier 2 electronics supplier in Asia, no backup, severity 4” and presses Analyse. Seven helper robots (agents) take turns. Here is when each one talks to the library, measured on a real run (about 11.5 seconds in total).

0 s3 s6 s9 s12 s
Agents live in backend/agents/. The Investigation step runs two branches in parallel: hybrid_retriever (calls trident_get_chunks + trident_search) and synapt_worker (calls trident_query + trident_get_procedures). Everything after that is local maths, ML and rules — no LLM.

The little helpers we built around the walkie-talkie

Real libraries are sometimes busy or closed. These helpers make sure our app never gets stuck.

🔌

The safety switch (circuit breaker)

If the library doesn't answer 3 times in a row, we stop calling for a minute instead of waiting and waiting. Then we try once more.

Library OK — calls go through
One breaker per tool in agents/synapt_tools.breaker_for; 3 failures open it, 60 s later one trial call (half-open). The API reports semantic_source and fallback_reason so a degraded answer is never hidden.
🎭

The secret-code decoder (region masks)

The library hides place names for privacy, writing [LOCATION_3] instead of “Asia-Pacific”. We learned which code means which place, so we can read the answers.

regions bridge in agents/synapt_tools.py: mask() before sending, unmask() after; tokens learned from returned case IDs and saved in artifacts/synapt_region_tokens.json.
🗄️

The name tag (provider id)

Every time we press a button, our shelf name is added for us, so we never read someone else's shelf by mistake.

call_tool() reads each tool's input schema and injects provider_id only where it is accepted (it is not, for example, on trident_feedback).
🔁

Try again (session refresh)

If the library says “who are you?” we show our card again. If it forgot our conversation, we say hello again.

401 → re-authenticate; 404 on the MCP session → new initialize handshake; tool errors (isError) raise SynaptError so callers can fall back.
🏠

Our own small library (fallbacks)

If the big library is closed, we still have a small one at home: keyword search and our own copies of all 100,000 cases. Answers are a bit less clever, but we still answer.

Local LSA semantic index + BM25 + profile match in services/data_store.py and agents/retrieval.py. Synapt's semantic leg found the right disruption type 87% of the time vs 68.5% for the local fallback.
🧪

The pretend-it's-broken lab

A button in our app that pretends the library is closed, so we can prove the helpers really work.

Fallback Lab (services/faults.py, services/fallback_lab.py): switches for all Synapt tools, graph-RAG only, or playbooks only. The self-test passes 15/15 with Synapt off.

Oopsies we found in the library

Synapt is a beta. We found these while building, worked around each one, and wrote them down for the Synapt team.

🧱 “Make a new idea” buttons are broken

The buttons that add new things to the spider web fail on the library's side.

trident_create_entity / create_concept / create_relationship fail with index_node() missing 'neo4j_id'. Fewer typed entities → graph confidence ≈ 0.58 and answers flagged “degraded”. Workaround: an ontology document so extraction creates the types.

🔓 One button can see other people's shelves

The “ask in database language” button isn't locked to our shelf, so we only allow 6 safe, pre-written questions.

trident_cypher is not tenant-scoped. We never send free-form Cypher; six fixed templates in GRAPH_INSIGHTS, each pinned to our provider_id.

⏳ The library says “slow down” quietly

When we send too many books at once, the library says “wait 47 seconds” — but as a normal answer, not as an error.

trident_ingest returns {"error": "rate_limited", "retry_after_seconds": N} as a result. Our ingest script now waits and retries, and the manifest never records a rejected file as sent.

🏷️ Sticker room has picky rules

Tickets must be uploaded as a spreadsheet, and the labelling button wants the ticket written as text.

The ticket gateway accepts .xlsx only (console upload; MCP can't create a ticket store) and trident_label_ticket needs ticket as a JSON string.

🗺️ The five rooms of the office

🧱 Substrate core

Where the library is built.

  • Context ProviderMake a shelf. Ours: supply_chain_disruptions (+ _v2).
  • Data IngestionPut books in: files, URLs, video, web scraping, code, tickets, SharePoint, Jira, Confluence, Salesforce, databases, REST APIs. Default: 512-word pages, 64 overlap.
  • Context GraphSee the spider web as a picture.
  • Query Context GraphChat with a query agent that shows its reasoning trace and a "context ledger".
  • Knowledge PackTeach the library your own kinds of knots and strings (custom entity + relationship types). 12 system types, 24 user-defined.

Where every answer is written down.

  • Audit LogsEvery login between services, every ingest, every LLM call, failed jobs, and the system versions.

🏭 How long the ingest conveyor belt takes

Average per file, platform-wide (Context Monitoring). End-to-end ≈ 58 s on average; 1,417 of 24,882 jobs (5.7%) ended dead-lettered. This is why our ingest script waits for rate limits and records a manifest instead of trusting one big upload.

🚀 Things the console offers that we could use next

🧩 Knowledge Pack → fix the 15% coverage

Define our own knot types — Supplier, Disruption, Strategy, Region, Playbook — and links like HIT_BY, RESOLVED_WITH, LOCATED_IN. The next ingest would then link entities properly instead of leaving 88% of them alone.

Other teams already have packs (for example an 11-entity / 14-relation network-operations pack). This replaces our ontology-document workaround and should raise graph confidence.

🪪 Agent Connector → let our app log in as an agent

Instead of a username and password, our app could get its own agent identity, with read-only access to just our shelf.

Federated identity (OAuth 2.0 / OIDC JWT) + scoped grants + token exchange, all audited. The right production setup for our MCP connector.

📥 More data sources

Real supplier tickets from Jira, playbooks from SharePoint or Confluence, or live data straight from a database or REST API.

We used file/content ingest only; the same trident_ingest path accepts these connector types.

Big words, small meanings

Big wordLike a 5-year-old would sayWhat it really is
MCPThe walkie-talkie language everyone agreed on.Model Context Protocol: a standard way for apps and AI tools to list and call tools (JSON-RPC 2.0 over HTTP).
ToolOne button on the walkie-talkie.A named function with an input schema, called with tools/call.
TokenThe library card.A bearer token from the auth service, sent in every request header.
ProviderOur own shelf.A tenant/namespace for our documents, graph and stores.
ChunkOne small page torn from a book.A passage of an ingested document, stored with an embedding for meaning search.
Knowledge graphA spider web joining ideas.Nodes (entities, concepts, procedures, steps) and edges in Neo4j.
Graph-RAGThe librarian reads pages, follows the web, then answers.Retrieval-augmented generation that also traverses the graph for context.
ConfidenceHow sure the librarian is, from 0 to 1.Synapt's scores: overall, knowledge, procedural and graph confidence.
IngestPutting new books on our shelf.trident_ingest: upload content; Synapt chunks it and extracts graph nodes.
Circuit breakerThe safety switch.Stops calling a failing service for a while so the app stays fast.
