Agent architecture: a supervisor and goal-driven agents

Inside the analysis there is no fixed pipeline. A Supervisor sits at the centre of a shared state (the blackboard). After every step it runs every agent whose goal is still open and whose inputs are ready, in parallel, and acts on the requests agents post. Each agent has its own goal and tools and decides its own next step. No LLM is involved.

Why these are agents

Each has a goal it checks, tools it chooses between, and a loop that adapts to what it observes. It grades its own result and can ask another agent for work. Their policies are rules we wrote, so they are reproducible and unit-tested.

What runs in parallel

Case search, the Synapt agent and the Impact agent all need only the incident, so the supervisor starts them together. Fusion waits for both investigation branches; the Planner waits for evidence and impact; then Recovery, Report and Judge.

What a redo looks like

If the Judge scores "consistency" low, it asks the Planner to re-plan without the current primary strategy. The supervisor resets only the plan and what depends on it, so recovery, the briefing and the audit re-run while the evidence is reused. One revision round is allowed.

How Synapt works

Synapt is a context substrate: a managed memory for AI applications. Instead of one vector index it keeps three linked stores (the "tri-store") and exposes them through the Model Context Protocol (MCP), so any agent can read, reason over, and write back to the same organisational memory.

The four memories

KnowledgeDocuments are chunked, embedded and indexed. trident_get_chunks returns the most similar passages. We ingested 43 Markdown files: 4,000 case narratives, 100k case profiles and aggregate statistics.
GraphEntities and relations extracted from the ingested text, stored in Neo4j. trident_query walks N hops from the entities in the question (BFS) and answers from that subgraph: graph-RAG.
ProceduresStep-by-step operating procedures. We load six response playbooks; trident_get_procedures fetches the one that matches the disruption type.
EpisodesWhat happened when the system was used: tickets, outcomes, feedback. trident_label_ticket labels a new ticket from similar past ones; trident_feedback records whether an answer helped.

Every answer carries quality signals: knowledge, procedural and graph confidence plus a degraded flag. We log them per request and show them next to DeepEval scores.

Timing (typical)

The supervisor starts case search, the Synapt agent and the Impact agent (Synapt precedents + cohort estimate) together; Synapt graph-RAG dominates wall time (≈ 10.5 s of an 11.8 s run). No LLM call. Each step streams to the UI as soon as it finishes (Server-Sent Events), so the operator sees results within seconds.
