Graceful degradation

Works with Synapt. Still works without it.

The workflow depends on one external service: Synapt (knowledge, graph-RAG answers, playbooks). An external LLM is used only as the independent judge in evaluation, never inside the workflow. Every Synapt step has a local fallback, so losing a service lowers quality instead of breaking the app. Pick a mode below to see exactly what changes.

The circuit breaker

Every Synapt call goes through one breaker (agents/synapt_tools.breaker_for). After 3 consecutive failures it opens, and calls skip Synapt instantly instead of waiting for timeouts. After a 60 s cooldown one call is allowed through (half-open); success closes it again. Try it:

What the operator sees

The API reports this honestly: every search result carries semantic_source (synapt, synapt+local or local-lsa) and a fallback_reason, and /api/health shows the breaker state. The UI shows a badge, so nobody mistakes a degraded answer for a full one.

Where the LLM is (and isn't)

Following the reference Synapt capstone, no agent calls an external LLM. Each step below runs on rules, Synapt and templates; the aicredits.in model only grades the output in evaluation.

Why the LLM was taken out of the workflow

In an earlier design the LLM wrote the plan and briefing. During a 25-case evaluation the gateway returned 402 Budget Exceeded after case 8, and every later analysis silently dropped to templates. Now the workflow never needs credits:

98/98golden-set fields classified by rules alone
11.5 sfull analysis, 0 LLM calls (10.6 s is Synapt graph-RAG)
100%briefings pass the fact-check

Caveat: the golden descriptions name the disruption type explicitly, which suits keyword rules; vague real-world text is the case to watch.

Try it live: the Fallback Lab

Everything on this page can be reproduced in the running app. Open Fallback Lab (sidebar → System), switch a dependency off, and press Run self-test.

Six switches

Synapt (all tools) · Synapt graph-RAG only · Synapt playbooks only · LLM judge · prediction models (→ cohort statistics) · live hazard feed. Each fails at the lowest level, so the real fallback code runs, and restores itself after a chosen time.

Self-test result (measured)

With the full workflow: all on 15/15 checks on the normal engines (including a live LLM-judge call); Synapt off 15/15 with the fallbacks; LLM judge + models + feed off 15/15, no crashes. With models off, cohort statistics gave 125 days full recovery vs 129 from the model for the same incident.

Why this design

For operations

A disruption assistant is needed most on the bad day, when networks and vendors are also under stress. A tool that stops when one dependency stops cannot be trusted in a war-room.

For Synapt

It shows Synapt's real value-add. Offline, you keep a decent case list. With Synapt, you get better recall, reasoning paths, playbooks and memory, with confidence signals that make the difference measurable.
