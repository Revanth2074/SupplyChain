Single operating mode

One mode: Synapt.

The workflow runs on Synapt: knowledge chunks, the knowledge graph, graph-RAG answers, response playbooks and case retrieval. Synapt is required. There is no local or degraded mode, so every analysis is produced the same way. An external LLM is used only as the independent judge in evaluation, never inside the workflow.

Step by step: what each node runs on

The ten LangGraph nodes, in order. The hybrid retriever and the Synapt worker run in parallel after the classifier. Synapt steps call Synapt tools; local steps are rules, statistics or ML on the local dataset. If a Synapt step fails, the workflow stops with an error.

When Synapt fails

Failures are reported, never hidden. Nothing switches to a different engine: the request that hit the problem returns an error, and the health endpoint records which tool failed and why.

At start-up

1 · connecting to Synaptchecks SYNAPT_USERNAME, SYNAPT_PASSWORD, SYNAPT_PROVIDER_ID, authenticates, MCP handshake
2 · loading dataCSV + BM25 index
3 · loading modelsload or train the ML predictors
4 · readyall endpoints serve
stage = errorSynapt not configured or unreachable: data endpoints return 503 and the console banner shows the start-up error.

During a request

  • Every Synapt call has a timeout; a timeout or tool error raises SynaptError.
  • /api/analyze and the live SSE stream end with an error event; no partial briefing is produced.
  • /api/ask and /api/synapt/* (including /api/synapt/label) return HTTP 502 with the Synapt error.
  • The next request tries Synapt again. There is no circuit breaker and no local semantic index.
The only deliberate skip is the use_graph=false option, which leaves out the graph-RAG step on request. It is an option, not a failure path.

Where the LLM is (and isn't)

Following the reference Synapt capstone, no agent calls an external LLM. Each step below runs on rules, Synapt and templates; the aicredits.in model only grades the output in evaluation.

Why the LLM was taken out of the workflow

In an earlier design the LLM wrote the plan and briefing. During a 25-case evaluation the gateway returned 402 Budget Exceeded after case 8, and every later analysis silently dropped to templates. Now the workflow never needs credits:

98/98golden-set fields classified by rules alone
11.5 sfull analysis, 0 LLM calls (10.6 s is Synapt graph-RAG)
100%briefings pass the fact-check

Caveat: the golden descriptions name the disruption type explicitly, which suits keyword rules; vague real-world text is the case to watch. If the judge LLM key is missing or the gateway is unreachable, evaluation scores with the rule rubric instead.

Why one mode

Consistent, auditable answers

Every briefing is built from the same sources: Synapt chunks and graph, Synapt playbooks, local statistics and models. A reviewer never has to ask which engine produced a given answer.

No silent quality drop

If Synapt cannot answer, the user sees an error instead of a weaker answer that looks like a normal one. semantic_source is always synapt when the semantic leg runs.

Simpler operations

One code path to test and monitor. No breaker state, outage switches or second index to keep in sync; /api/health names the last failing tool and its error.

The trade-off

A Synapt outage makes analysis, Q&A and the graph features unavailable until the connection is back. Keyword search, predictions and the local dashboards keep working once start-up has completed.
