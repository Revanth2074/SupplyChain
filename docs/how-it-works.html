The problem

When a supplier goes down, the team has three questions and no fast way to answer them.

1
Has this happened before?
…and how was it resolved?
2
How bad will it get?
Which factors drive production impact and financial loss?
3
What should we do?
Which response worked for similar cases, and how fast did it recover?
Today
  • Search spreadsheets and old e-mails by hand
  • Keyword search misses "ransomware" when you typed "IT outage"
  • Estimates are gut feel, with no ranges
  • A plain chatbot invents numbers and case IDs
With the assistant
  • Semantic + keyword + profile search over 100,000 cases
  • ML predictions with P10–P90 ranges and the reasons behind them
  • Strategies ranked by what actually recovered fastest
  • Every claim fact-checked against the evidence

Why: what drives full recovery

Severity dominates; a backup supplier saves about 26 days on average (90 → 64). Disruption type matters mostly through severity. The what-if simulator shows how each change moves the prediction.

Decide & act

From analysis to an owned, tracked response.

Priority = 35% severity + 30% impact + 25% loss + 10% risk

P1war-room in 4 h
P2plan in 24 h
P3review in 3 days
P4monitor weekly

Incidents get an SLA clock and an escalation chain; breaches turn red on the Incident Desk.

Decision Studio: compare options in money

Net benefit vs. doing nothing for the same cyber-attack example: loss avoided − extra cost of acting, scaled by outage days. Recommended: release the buffer (+$390k, 18 days sooner). Cost assumptions are editable.

Early warning

Live GDACS hazard feed + manual signals → region × type watchlist (60% likelihood, 40% predicted impact).

Act → learn

Closing an action records the real outcome. Ratings re-weight strategies (×0.85–1.15), outcomes retrain the models, verdicts go to trident_feedback.

Building on Synapt: what I found

I used every part of the product and hit its edges.

BUG
trident_create_entity / create_concept fail
Server error index_node() missing 'neo4j_id'. Few typed entities → graph confidence ~0.57 and answers flagged "degraded". Worked around with an ontology document.
SECURITY
trident_cypher is not tenant-scoped
Free-form Cypher could read other providers' data. I only send six fixed templates pinned to our provider_id.
UX
PII masking hides regions
"Asia-Pacific" returns as [LOCATION_x], breaking filters. Built a token ↔ region bridge.
DX
Ticket store: .xlsx only; label_ticket wants a JSON string
Both undocumented. Loader writes .xlsx; service serialises tickets.

Suggestion: expose the graph-confidence breakdown per hop, and a tenant-scoped read-only Cypher endpoint. Both would make graph-RAG answers easier to trust and debug.
