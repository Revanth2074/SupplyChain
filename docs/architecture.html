How Synapt works

Synapt is a context substrate: a managed memory for AI applications. Instead of one vector index it keeps three linked stores (the "tri-store") and exposes them through the Model Context Protocol (MCP), so any agent can read, reason over, and write back to the same organisational memory.

The four memories

KnowledgeDocuments are chunked, embedded and indexed. trident_get_chunks returns the most similar passages. We ingested 43 Markdown files: 4,000 case narratives, 100k case profiles and aggregate statistics.
GraphEntities and relations extracted from the ingested text, stored in Neo4j. trident_query walks N hops from the entities in the question (BFS) and answers from that subgraph: graph-RAG.
ProceduresStep-by-step operating procedures. We load six response playbooks; trident_get_procedures fetches the one that matches the disruption type.
EpisodesWhat happened when the system was used: tickets, outcomes, feedback. trident_label_ticket labels a new ticket from similar past ones; trident_feedback records whether an answer helped.

Every answer carries quality signals: knowledge, procedural and graph confidence plus a degraded flag. We log them per request and show them next to DeepEval scores.

Timing (typical)

Synapt and the local search run in parallel; the LLM steps dominate wall time. Each step streams to the UI as soon as it finishes (Server-Sent Events), so the operator sees results within seconds.
