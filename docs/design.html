Hybrid retrieval: Reciprocal Rank Fusion

Three ranked lists are merged by rank, not by score, so scores on different scales never need calibrating.

score(case) = Σlegs wleg / (60 + rankleg)   ·   wsemantic = 0.6, wkeyword = 0.4, wprofile = 0.6   →   final = 0.5 · fused + 0.5 · attribute similarity

        Prediction models

        Scikit-learn HistGradientBoosting with native categorical support, trained on all 100,000 rows (80/20 split). Each regression target also has P10 and P90 quantile models for an 80% range.

        Model card

        TargetR² / AUCMAEP10–P90 coverage

        Read honestly: production impact is predictable (R² 0.70). Revenue and recovery are noisier (R² 0.27–0.40), which is why every prediction shows a P10–P90 range and an "insufficient history" warning instead of a single number.

        What drives each prediction (permutation importance)

        Local explanations use the same idea per incident: prediction with the real value minus prediction with that feature reset to the baseline.

        Agent contracts

        Seven agents, each with one job, a typed input and output, and a deterministic fallback. Streamed to the UI over Server-Sent Events.

        The anti-hallucination chain

        1 · before

        Guardrails block injection and off-topic input, redact PII and validate fields against the dataset vocabulary.

        2 · during

        The LLM receives exact figures and case IDs as JSON evidence; it is told it may not invent numbers or attach case IDs to the new incident. Strategy names outside the allowed list are replaced.

        3 · after

        A deterministic fact-check rejects unknown case IDs, placeholders and amounts / percentages not in the evidence, and triggers one rewrite. Then the LLM judge scores six criteria.

        The feedback loop

        Rating

        1–5 stars + chosen strategy → strategy boost per (type, strategy), clamped to ×0.85–1.15 so a few votes cannot flip the ranking.

        Outcome

        Real recovery days and loss reported on the Incident Desk → stored as training rows → models retrain on demand.

        Synapt

        Every verdict is sent to trident_feedback; low-rated inputs are replayed as regression cases in the next evaluation.

        UI design

        Pages are grouped by the stage of the job, not by technology, so a non-expert can follow the story left to right. Every page has an ⓘ drawer that explains what it shows and how to read it.

        Plain language first

        Jargon terms are underlined; hovering shows a one-line glossary definition. Numbers come with their range and what they mean.

        Motion with meaning

        Animations show something real: agents lighting up as they finish, numbers counting to their value, flights following real taxi / take-off / landing phases.

        Light, calm palette

        One accent colour per stage; red is reserved for P1 and breaches. Works at phone width; the 3D view is lazy-loaded.
